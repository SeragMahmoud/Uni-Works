# Project Overview

The SPM package documents how IISS was managed from initiation to closure. It is a documentation-first project rather than a software runtime.

## Original Artifact Catalogue

| Original file | Lifecycle area | Purpose |
| --- | --- | --- |
| `feasibility-IISS.docx` | Initiation | Evaluate viability. |
| `IISS_Business_Case_v2.docx` | Initiation | Explain value and justification. |
| `IISS_Project_Charter_v2.docx` | Initiation | Authorize scope, roles, and objectives. |
| `SWOT_Analysis_IISS.docx` | Initiation | Analyze strengths, weaknesses, opportunities, and threats. |
| `IISS_Communication_Plan.docx` | Planning | Define stakeholder communication. |
| `IISS_Training_Plan.docx` | Planning | Plan readiness and training. |
| `IISS_Individual_Goal_Template_v2.docx` | Planning | Align individual responsibilities. |
| `IISS_RAID_Log_v2.docx` | Planning/control | Track risks, assumptions, issues/actions, and dependencies. |
| `IISS_Change_Request_v2.docx` | Monitoring/control | Govern changes to scope or plan. |
| `IISS_Closure_Report.docx` | Closure | Summarize completion and lessons learned. |
| `IISS_Project_Kickoff.pptx` | Presentation | Stakeholder kickoff material. |

## Publication Boundary

The public repository summarizes the deliverables instead of redistributing Office files. This avoids publishing private metadata while still demonstrating project-management structure.
