# System Design

This project uses a documentation system rather than an executable architecture.

## Folder Design

| Folder | Design intent |
| --- | --- |
| `docs/01_initiation` | Ordered startup and authorization artifacts. |
| `docs/02_planning` | Communication, training, goals, and RAID planning. |
| `docs/03_monitoring-and-control` | Change-control evidence. |
| `docs/04_closure` | Completion and closeout evidence. |
| `microsoft-project` | Schedule-source and planning-tool area. |
| `diagrams` | WBS, Gantt, milestone, and network diagram outputs. |
| `presentations` | Stakeholder presentation material. |
| `templates` | Reusable PM templates. |

## Naming Strategy

The repository uses numbered prefixes where ordering matters and descriptive file names where discoverability matters. This supports review by faculty, teammates, and recruiters.
