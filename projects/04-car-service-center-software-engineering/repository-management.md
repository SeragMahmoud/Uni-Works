# Repository Management Guide

## Folder Rules

- Keep implementation projects under `source/`.
- Keep written engineering deliverables under `docs/`.
- Keep visual models and design exports under `diagrams/`.
- Keep screenshots and videos under `demo/`.
- Keep visual support files under `assets/`.
- Keep final summaries under `reports/`.
- Keep compressed original packages and metadata under `archive/`.

## Naming Convention

Use numeric prefixes for ordered documentation and clear folder names for engineering topics:

```text
01_requirements
02_use-cases
05_testing
class-sequence
architecture
```

## GitHub Presentation

The repository is structured for clear GitHub review:

1. Root README introduces the whole project.
2. `docs/` explains the analysis and testing material.
3. `diagrams/` shows visual software engineering models.
4. `source/` contains runnable Java implementations.
5. `archive/` preserves original packaged material.
