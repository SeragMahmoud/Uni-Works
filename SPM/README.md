# IISS Software Project Management Case Study

> A portfolio-ready Software Project Management repository for the IISS graduation project.

## Project Overview

IISS is documented in the project artifacts as an Intelligent/Interactive Interview Simulation and Evaluation System: an AI-supported platform for interview practice, recruiter-led interview sessions, candidate evaluation, and analytics. This repository focuses on the Software Project Management work behind the graduation project rather than the application source code.

The repository shows how project management practices supported the project from initiation through planning, monitoring, control, and closure. Microsoft Project was used as the central planning tool for scheduling, dependencies, milestones, and resource planning.

## Objectives

- Present the IISS management work in a clean, professional GitHub structure.
- Preserve the original academic project artifacts while improving navigation and naming.
- Demonstrate PMBOK-inspired planning across scope, schedule, communication, risk, quality, stakeholder, and closing activities.
- Make the repository useful for academic review, recruiter review, and future project teams.

## Microsoft Project Usage

Microsoft Project was used to plan and control the IISS schedule. The `.mpp` file is stored as the source of truth for the working schedule:

- task sequencing and work breakdown planning
- activity dependencies and timeline coordination
- milestone tracking
- resource allocation planning
- baseline and tracking readiness
- export support for Gantt charts, schedule reports, and stakeholder updates

See [microsoft-project/](microsoft-project/README.md) for the artifact layout.

## Project Timeline

The management lifecycle is organized into four phases:

1. Initiation: feasibility, business justification, project authorization, and strategic analysis.
2. Planning: communication, training, resource goals, risk, assumptions, issues, and dependencies.
3. Monitoring and Control: formal change control and project governance.
4. Closure: project sign-off, lessons learned, and transition-oriented review.

## Lessons Learned

Software Project Management improved the IISS project by making the work visible, traceable, and reviewable. The artifacts show how early justification, structured planning, risk awareness, stakeholder communication, and formal control documents reduced ambiguity and helped the team manage a complex AI-enabled graduation project.

## Repository Highlights

- Students can use this as a model for organizing academic project management deliverables.
- Recruiters can quickly evaluate planning discipline, documentation quality, and ownership.
